# 基于 ArceOS 的轻量级高性能防火墙 (axfirewall) 中期进展报告

### 一、研究背景与目标
* **研究背景**：ArceOS 等 Unikernel 系统在云原生与微服务场景应用广泛，但缺乏原生、高效的网络安全过滤组件。传统 Linux iptables 基于规则链逐条线性匹配，规则规模扩大时单包处理延迟呈 $O(N)$ 急剧上升。
* **课题目标**：参考 SIGCOMM CCR 2019 论文《Securing Linux with a Faster and Scalable Iptables》的核心机制，在 ArceOS 裸机（`no_std`）环境下构建原生包过滤模块 `axfirewall`，实现 $O(1)$ 级多维分类引擎与早期短路过滤。

---

### 二、系统设计与核心实现
1. **驱动边界零拷贝拦截**：在 `modules/axnet` 的 `RxToken::consume` 处切入过滤逻辑，使用 `smoltcp::wire` 零拷贝提取报文五元组，对 `Drop` 报文直接阻断并安全回收环形缓冲区描述符。
2. **LBVS 向量匹配引擎**：
   * 将规则状态抽象为 1024 位定长位向量（`[u64; 16]`）。
   * 将多维匹配转化为按位与（`AND`）操作，利用 64 位 CPU 寄存器位级并行单周期判定 64 条规则。
   * 使用硬件指令 `trailing_zeros` 快速选取最高优先级规则。
3. **哈希多维索引优化**：为目的端口与目的 IP 构建 256 桶轻量哈希映射，消除多维键查找阶段的线性扫描瓶颈。
4. **Early-Break 短路机制**：当端口等前置字段未匹配且无通配符时，临时位向量归零，引擎直接短路退出，跳过后续协议与 IP 运算。
5. **全局规则管理器**：利用 `spin::Mutex` 维护内核单例，实现控制面（规则构建）与数据面（只读查表）解耦，数据面过滤零堆内存分配。

---

### 三、阶段性效果评估
测试基于 x86_64 平台的 CPU 时间戳计数器（TSC，`_rdtsc()` 指令）精确测量单包分类周期数：

#### 1. 多维规则扩展性测试 (Linear vs LBVS)
| 规则规模 ($N$) | 传统线性遍历 (Cycles) | LBVS 位向量匹配 (Cycles) | 加速比 (Speedup) |
| :---: | :---: | :---: | :---: |
| **10** | 322 | 664 | 0.48x |
| **50** | 1,098 | 553 | 1.99x |
| **100** | 2,072 | 550 | 3.77x |
| **500** | 10,162 | 533 | 19.07x |
| **1000** | 20,265 | 536 | **37.81x** |

* **分析**：传统线性遍历随规则增长呈严格的 $O(N)$ 性能衰退；LBVS 在 50 至 1000 条规则下耗时始终平稳在 530~550 cycles，展现出明确的 $O(1)$ 常数级复杂度，千条规则下加速比达到 **37.81 倍**。

#### 2. Early-Break 短路优化收益 (N = 1000)
* **全流水线合法报文耗时**：547 cycles
* **扫描/未授权报文短路耗时**：152 cycles
* **计算开销削减**：**72.2%**
* **分析**：针对未开放端口的扫描或异常流量，引擎在第一阶段即可提前返回，单包处理开销降低超七成，有效缓解恶意流量冲击。

#### 3. 端到端功能测试
* 在 `httpserver` 实例中成功拦截目标端口（5555）请求，控制台完整记录客户端 SYN 报文的指数退避重传，验证了阻断的准确性与协议栈隔离效果。

### 四、后续工作规划
1. **有状态连接跟踪 (Conntrack)**：实现双向五元组归一化键与 TCP 状态机，支持已建连数据包走 Fast-Path 快速放行。
2. **补齐 TX 出站拦截**：在 `TxToken` 补充过滤钩子，实现进出双向控制。
3. **扩展规则表达**：引入 CIDR 子网掩码与连续端口范围匹配支持。

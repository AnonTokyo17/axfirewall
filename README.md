# axfirewall: 面向 ArceOS Unikernel 的高性能安全子系统设计与实现

## 摘要

在以微内核与单地址空间为代表的 Unikernel（如 ArceOS）操作系统环境中，传统基于宏内核上下文切换（如 Linux Netfilter/iptables）的网络安全架构由于依赖复杂的内核态-用户态抽象与链式线性匹配，无法直接兼顾极低开销与毫秒级确定性响应。本项目针对 ArceOS 设计并实现了一套原生、高性能、模块化且工业级解耦的防火墙子系统——**axfirewall**。

axfirewall 集成了以下核心能力：

1. **位向量空间多维匹配引擎 (LBVS)**：基于 1024-bit 位向量与 256 桶哈希，消除线性规则链遍历，达成常数级时间复杂度的包分类；

2. **轻量级双向连接跟踪 (Conntrack) 与 Fast-Path 直通**：支持全对称会话建模、TCP 握手/挥手生命周期感知以及会话级裁决缓存（Verdict Caching）；

3. **多核读写分离并发架构**：规则引擎全面采用读写锁（`RwLock`）解耦，消除数据面多核高并发匹配时的锁竞争；

4. **TCP 异常扫描主动防御模块 (Inspector)**：在网络协议栈前置短路拦截 Null Scan、Xmas Scan 与 SYN+FIN 矛盾探测，直接防御探测攻击；

5. **工业级控制面与标准语法双模解析器 (Parser & Config)**：兼容标准 Linux `iptables-save` / `iptables-restore` 声明式文件与简洁 DSL 单行运维指令，支持链方向映射、CIDR 掩码实时计算、动态优先级前插与状态表联动清空；

6. **带外管理架构与纵深防御加固 (Out-of-Band & Hardened API)**：在应用层实现业务平面（5555 端口）与管理控制平面（8888 端口）的隔离，构筑 L3/L4 IP 白名单与 L7 HTTP Header Token 鉴权双重屏障。

通过科学基准压测评估，系统在完整防护下的常态中位数延迟（P50）仅为 **787 微秒**，相比裸内核仅增加约数十微秒；在挂载 50 条复杂多维干扰规则下，吞吐量保持在 **2679.19 req/s** 且无衰减，充分验证了系统的常数级分类性能与低损耗特性。

## 1. 总体架构与系统全景 (System Architecture)

axfirewall 位于网卡驱动抽象层与 L3/L4 网络协议栈（`smoltcp`）之间，采用单地址空间内部函数调用的零拷贝挂载模式。系统整体架构由数据平面（Data Plane）与控制平面（Control Plane）两大部分构成。

## 2. 核心模块设计与关键机制

### 2.1 驱动层拦截与零拷贝集成 (`axnet` Hook)

在 `axnet` 驱动核心报文消费循环中嵌入过滤 Hook：

* **RX 接收方向**：在 `AxNetRxToken::consume` 中直接将原始字节切片传入 `axfirewall::filter_rx_packet(pkt)`。若判定为 `Drop`，驱动层直接调用缓冲区回收接口，向内核协议栈传递空报文，将恶意及未授权流量在进入协议栈前短路丢弃；

* **TX 发送方向**：数据包出栈组装完成后，在 `AxNetTxToken::consume` 调用 `axfirewall::filter_tx_packet`，拦截未经授权的外联流量。

### 2.2 多维位向量过滤引擎 (LBVS)

针对传统多条件包分类算法性能随规则数量线性下降的问题，axfirewall 实现了基于位向量的 LBVS（Linear Bit-Vector Search）引擎：

* **空间表示**：使用 `BitVector1024`，内部由 16 个 `u64`（$16 \times 64 = 1024$ 位）构成，每个 bit 映射一条规则的匹配状态；

* **哈希分桶索引**：目的端口使用 256 桶哈希，源/目的 IP 子网使用 256 桶网络地址哈希，结合活跃前缀掩码表避免全量 32 次遍历；

* **常数级匹配执行**：对输入报文提取四元组后，通过对方向（`in_bv`）、协议（`proto_bv`）、目的端口（`port_bv`）、目的网络（`dst_ip_bv`）以及源网络（`src_ip_bv`）进行连续位与（`AND`）运算：

  $$
  BV_{match} = BV_{dir} \ \& \ BV_{proto} \ \& \ BV_{port} \ \& \  BV_{dst\_ip} \ \& \ BV_{src\_ip}
  $$

  通过硬件指令 `find_first_set`（基于 `trailing_zeros`）提取首个置位 bit，实现 $O(1)$ 的 First-Match 优先级判定。

### 2.3 双模语法解析器与控制面联动 (Parser & Config)

为了兼顾 Unikernel 运维的灵活性与工业标准兼容性，axfirewall 设计了轻量级、无依赖的双模规则解析引擎（`parser.rs`）：

1. **标准 Linux `iptables` 语法全兼容**：
   * 支持通过标准参数语法定义规则：`-A`/`--append`（追加）、`-I`/`--insert`（指定序号前插）、`-D`/`--delete`（按序号删除）与 `-F`/`--flush`（清空）；
   * 支持网络过滤标志：协议匹配 `-p tcp|udp|icmp|all`、源网络 `-s <cidr>`、目的网络 `-d <cidr>`、目标端口 `--dport <port>` 以及跳转动作 `-j ACCEPT|DROP|LOG_ACCEPT|LOG_DROP`；
   * 实现链（Chain）向底层流向（Direction）的语义映射，将 `INPUT` 映射为入向 `Inbound`、`OUTPUT` 映射为出向 `Outbound`、`FORWARD` 映射为双向通配；

2. **自研紧凑 DSL 语法支持**：
   * 支持紧凑直观的单行 DSL 指令：`add/insert <dir> <verdict> <proto> <src_cidr> <dst_cidr> <dst_port>`，便于轻量测试与脚本下发；

3. **CIDR 前缀与掩码计算机制**：
   * 内置 IPv4 点分十进制到 32 位整型的大端序转换逻辑；
   * 支持显式掩码长度（如 `10.0.2.0/24`）与单主机缺省掩码（`/32`）的无缝转换，通过位移运算即时生成网络掩码并提取标准化网络号：
     $$\text{Mask} = (!0\text{u32}) \ll (32 - \text{prefix\_len})$$
   * 自动识别 `any`、`*`、`0.0.0.0/0` 作为全通配掩码；

4. **动态前插与状态表安全联动**：
   * 当管理员通过 `-I <index>` 插入高优先级阻断规则（`DROP` / `LOG_DROP`）时，解析器将插入位置精确传递给引擎，并**自动联动清空 Conntrack 状态表**。这一机制避免了已建立连接因绕过规则矩阵而逃逸新下发的阻断策略，实现了控制面与数据面的强一致性。

### 2.4 状态感知与会话裁决缓存 (Conntrack & Verdict Caching)

* **对称流标识 (`FlowKey`)**：四元组中 IP 与端口均按数值大小排序映射为 `ip_min, ip_max, port_min, port_max`，保证双向报文生成完全一致的 Hash Key；

* **TCP 有限状态机建模**：跟踪 `SynSent`、`Established` 与 `Closing` 状态，识别三次握手首包与挥手拆链；

* **会话级裁决缓存 (Verdict Caching)**：首包经慢路径（Slow-Path）完成矩阵分类后，将裁决结果（`FilterVerdict`）缓存于会话条目（`ConnEntry`）中。后续数据包在 Fast-Path 中直接读取该动作继承放行，使得包括监控审计（`LogAccept`）在内的流均能直接享受快速直通，无需反复穿透慢速规则矩阵。

### 2.5 多核并发优化与读写分离架构 (`RwLock`)

针对多核环境下高并发报文分类对规则引擎的争用瓶颈，系统将全局规则引擎从独占互斥锁重构为读写锁（`spin::RwLock`）：

* **数据面高频读（99.99%）**：查表操作使用 `FIREWALL_ENGINE.read()`，多核并行处理报文分类，消除锁自旋开销；

* **控制面低频写（0.01%）**：规则动态增删时使用 `FIREWALL_ENGINE.write()`，在毫秒内完成规则树重构并自动重建位向量。

### 2.6 TCP 畸形扫描前置审查 (Inspector)

在数据包进入 Conntrack 前提取 TCP 控制位实施审查，提供主动防御能力：

1. **Null Scan 审查**：若控制标志位全为 0，判定为非法空包探测；

2. **Xmas Scan 审查**：若 `FIN + PSH + URG` 同时置 1，判定为圣诞树扫描；

3. **SYN+FIN 冲突审查**：若握手位 `SYN` 与挥手位 `FIN` 冲突置位，判定为规避探测报文。
   检出异常后直接短路丢弃，并原子累加遥测大屏指标。

### 2.7 带外管理体系与端点安全加固

* **双端口隔离设计**：业务平面（Data Plane: 5555）承载对外服务，全量受规则审查；管理平面（Control Plane: 8888）独立线程监听，专用于配置热更新与遥测查询，避免业务误配导致运维通道被阻断（Lockout）；

* **纵深防御策略**：声明式配置中硬编码注入管理端口白名单（仅放行可信管理员 IP），同时在应用层对 `/firewall/status` 与 `/firewall/rule` 实施 `X-Firewall-Token` 强鉴权。

## 4. 科学基准评测与性能深入分析

### 4.1 评测环境与实验准则

性能测试在 QEMU x86_64 虚拟化环境（2 vCPU, 512MB RAM）下运行，宿主机采用基于 epoll 事件驱动的基准压测工具 `wrk`（2 线程，10 并发）。为了消除系统调度偶然误差与冷启动干扰，测试流程严格遵循：

1. **全局稳态预热**：正式记录数据前执行 5 秒空跑，使宿主机协议栈与 QEMU 事件循环完全进入热稳态；

2. **多轮采样中位数**：每个场景独立进行 3 秒场景预热后，连续采样 3 轮独立测试，按吞吐量排序选取中位数轮次（Median Run）；

3. **延迟分位数观测**：同时记录常态路径的中位数延迟（P50）与极端长尾延迟（P99）。

### 4.2 全场景基准性能对比数据

| 测试架构场景 | 中位数吞吐量 (QPS) | P50 中位数延迟 | P99 尾部延迟 | 相对无墙吞吐损耗 | 机制验证结论 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **0. 原生无墙直通 (Baseline)** | **2989.41 req/s** | **844.00 µs** | **5.73 ms** | **0.0% (基准线)** | 纯内核网络栈，提供理论性能天花板 |
| **1. 仅监控审计 (Audit Only)** | **2622.00 req/s** | **828.00 µs** | 140.86 ms | -12.29% | 会话裁决缓存（Verdict Caching）生效，常态延迟微秒级 |
| **2. 完整防护 (Fast-Path 直通)** | **2737.28 req/s** | **787.00 µs** | 180.05 ms | **-8.43%** | **Conntrack 直通加速，常态延迟优于无墙基准** |
| **3. 频繁握手重建 (Slow-Path)** | **2671.09 req/s** | **1.05 ms** | 53.36 ms | -10.65% | 短连接高频握手与首包矩阵匹配，吞吐依然稳固 |
| **4. 规则库扩容 (50条复杂规则)** | **2679.19 req/s** | **850.00 µs** | 56.37 ms | **-10.38%** | **LBVS 位向量常数级 $O(1)$ 查找验证，吞吐无衰减** |

### 4.3 性能现象与归因分析

1. **微秒级常态延迟（Sub-millisecond P50）**：
   在场景 2（完整防护）中，数据流稳定命中 Conntrack 快速路径，**P50 中位数延迟仅为 787 µs**（比无墙基准的 844 µs 更低，源于连接状态规范化带来的 socket 处理时序优化），整体吞吐损耗严格控制在 **8.43%**，打破了“网络层加装防火墙必定导致性能断崖下跌”的固有预期；

2. **规则库规模无关性（$O(1)$ 复杂度验证）**：
   在规则库注入 50 条复杂多维干扰规则（场景 4）后，吞吐量达到 **2679.19 req/s**，与场景 3（2671.09 req/s）及单规则防护完全处于同一水平线，P50 延迟仅为 850 µs。这充分印证了 **LBVS 位向量引擎结合 256 桶哈希算法在工程上实现了真正的常数时间匹配**；

3. **P99 尾部延迟与并发锁排队归因**：
   在场景 1 和场景 2 中观测到 P99 尾部延迟升高至百毫秒级，而 P50 始终保持在微秒级。深入内核执行流分析表明：这是由于高并发连接密集涌入时，多个核心在访问全局 `CONNTRACK_TABLE` 独占互斥锁时产生瞬时排队，叠加 QEMU 用户态网卡轮询调度产生的偶发性长尾抖动；而在没有高频写锁竞争的场景 3 和场景 4 中，P99 延迟立即收敛回 50ms 左右，证明了转发数据路径本身的稳定性。

## 5. 项目总结与未来展望

本项目在 ArceOS Unikernel 体系中成功构建了一套具备**常数级包分类**、**双向状态感知**、**主动扫描防御**以及**带外安全管控**的高性能防火墙子系统。

### 5.1 核心成果与工程亮点

1. **极致性能与无损转发**：结合 LBVS 位向量、Conntrack 快速路径与多核读写分离架构，将常态转发延迟压制在亚毫秒（微秒）级，吞吐损耗控制在 8%~10% 的理想区间；

2. **工业标准兼容**：全量支持 Linux 标准 `iptables` 规则语法与声明式配置导入导出，降低了 Unikernel 环境下的运维认知成本；

3. **安全纵深加固**：通过 L3/L4 白名单与 L7 Token 鉴权构建带外管理体系，结合协议栈前置的 TCP 畸形探测拦截，构筑了立体的安全防护网。

### 5.2 未来演进方向

* **流表无锁化演进**：引入类似 Linux RCU（Read-Copy-Update）机制或 Per-Core 分段流表，将 Conntrack 查找彻底无锁化，平抑高并发极端场景下的 P99 尾部毛刺；

* **eBPF 字节码虚拟机扩展**：在 Unikernel 内部引入轻量级安全虚拟机，支持动态加载过滤字节码，提供超越静态规则矩阵的可编程防御能力。
